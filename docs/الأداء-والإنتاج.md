# الأداء والإنتاج — بن مفيد

## ما يُنفَّذ في الخلفية (Queue)

بعد كل **طلب مكتمل** (سفري POS أو إغلاق طاولة):

- تحديث ملخص المبيعات اليومي (`daily_sales_summaries`)
- إبطال كاش لوحة التحكم والتقارير

بعد **طلب موقع** (سفري/توصيل):

- إشعار المديرين (قاعدة بيانات Filament)

بعد **فشل طباعة**:

- إشعار المديرين عبر Queue

## تشغيل الـ Queue

```bash
php artisan queue:work --tries=3
```

للإنتاج يُفضّل:

```env
QUEUE_CONNECTION=redis
CACHE_STORE=redis
```

ثم:

```bash
php artisan config:cache
php artisan route:cache
php artisan view:cache
```

## ملاحظة مهمة

**المخزون والمطبخ** يبقيان متزامنين مع الطلب (داخل Transaction) حتى لا يُباع منتج غير متوفر. ما يُؤجَّل هو التقارير والإشعارات فقط — وهذا هو النموذج الصحيح لأنظمة POS.
